JOURNIQ AI - USER MANUAL
========================

Project:
JourniQ AI - AI-powered Sri Lankan tourism platform

Purpose:
JourniQ AI helps tourists discover Sri Lankan destinations, find hotels,
book cultural/community experiences, receive personalized recommendations,
use an AI trip planner, chat with providers, and manage their travel profile.

The platform also gives hotel owners and activity providers dashboards to
manage listings, bookings, images, messages, revenue, and AI insights. Admins
manage users, approvals, destinations, listings, analytics, reports, and system
quality.


USER ROLES
==========

JourniQ AI has four main user roles:

1. Tourist
   Uses the public travel platform, receives recommendations, books hotels and
   experiences, chats with providers, and manages a personal travel profile.

2. Hotel Owner
   Registers as a hotel partner, waits for admin approval, then manages hotel
   profile, rooms, images, availability, bookings, messages, revenue, and market
   insights.

3. Activity Provider
   Registers as an activity provider, waits for admin approval, then manages
   local experiences, calendars, images, bookings, messages, community profile,
   revenue, and AI insights.

4. Admin
   Manages platform approvals, users, hotels, experiences, bookings,
   destinations, analytics, AI monitoring, recommendation audit, reports,
   commission, help messages, and settings.

TOURIST USER MANUAL
===================

Tourist Registration
--------------------

1. Go to:

   http://localhost:3000/register

2. Select Tourist.

3. Enter account details:

   - Name
   - Email
   - Password
   - Confirm password
   - Phone
   - Country
   - Accept terms acknowledgement

4. After account creation, the system asks travel preference questions one by
   one.

5. Select preferences such as:

   - Travel interests
   - Preferred places
   - Activity types
   - Accommodation styles
   - Travel style
   - Budget
   - Travel pace

6. Finish onboarding.

7. The system saves preferences to personalize destinations, hotels,
   experiences, recommendations, and AI trip planning.

8. A verification email is sent to the tourist email address.


Tourist Login
-------------

1. Go to:

   http://localhost:3000/login

2. Enter email and password.

3. Click Login.

4. After successful login, the tourist is redirected to the tourist profile.


Email Verification
------------------

1. Open the verification email sent by JourniQ AI.

2. Click the Verify Email button.

3. The browser opens:

   http://localhost:3000/verify-email

4. If the token is valid, the email is marked as verified.

5. If the link is expired, request a new verification email from the verify
   email page.


Forgot Password
---------------

1. Go to:

   http://localhost:3000/forgot-password

2. Enter the account email.

3. Click Send reset email.

4. Open the password reset email.

5. Click the reset link.

6. Enter a new password and confirm it.

7. Login again with the new password.

EMAIL BEHAVIOR
==============

Emails are sent for:

- Tourist verification
- Password reset
- Provider registration
- Admin provider registration notification
- Provider account approval
- Provider account rejection
- Hotel listing approval/rejection
- Experience listing approval/rejection
- Booking request confirmation
- Booking request notification to provider
- Booking status updates

If an email is not received:

1. Check spam folder.
2. Confirm backend is running.
3. Confirm Gmail SMTP works:

   cd /Users/yasiru_nisal/Desktop/research/backend
   npm run test:email -- your-email@gmail.com

4. Confirm backend/.env has:

   GMAIL_USER
   GMAIL_APP_PASSWORD
   EMAIL_FROM
   FRONTEND_URL

5. Restart backend after changing .env.

SECURITY NOTES
==============

- Admin registration is disabled publicly.
- Provider accounts must be approved before login.
- JWT authentication protects dashboards.
- Role-based routes separate tourists, hotel owners, activity providers, and
  admins.
- Password reset uses secure temporary tokens.
- Email verification uses secure temporary tokens.
- Secrets must stay in .env files, not frontend code.


LOGOUT
======

After logout, the local token is removed and the user must login again.


SUPPORT / TROUBLESHOOTING
=========================

Problem: Tourist cannot login
Solution:
- Check email and password.
- Use forgot password if needed.
- Confirm backend is running.

Problem: Provider cannot login
Solution:
- Provider account may still be pending.
- Admin must approve the account first.

Problem: Hotel or experience does not appear publicly
Solution:
- Admin must approve the hotel/experience listing.
- Check listing status in admin panel.

Problem: Booking email not received
Solution:
- Check Gmail SMTP settings.
- Run backend email test.
- Check spam folder.

Problem: Chat not updating
Solution:
- Confirm backend Socket.IO server is running.
- Confirm frontend socket URL points to backend.

Problem: AI recommendations feel empty
Solution:
- Complete tourist onboarding preferences.
- Use trip planner once.
- Search recommendations with interests/district/budget.
- Add approved hotels, experiences, and destinations.
